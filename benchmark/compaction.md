# 压缩抗性：skill（历史驻留）vs 插件（系统提示驻留）

- 压缩模型: 10 轮会话 → 保留最近 2 轮 + 212 字符主题级摘要（摘要由用户文本生成，不含工具输出/路径/命令——与各平台 auto-compact 行为一致）
- 插件臂的清单注入在系统提示（每请求重建，压缩不可及）；skill 臂的说明与索引在消息历史（压缩对象）

| 存活维度 | skill（历史驻留） | 插件（系统提示驻留） |
|---|---|---|
| KB 访问指引（工具/命令名） | 0% (0/3) | 100% (3/3) |
| bundle 清单（知识库存在且可知） | 0% (0/2) | 100% (2/2) |
| 触发指引（何时该查知识库） | 0% (0/2) | 100% (2/2) |
| 已加载概念正文（压缩必然丢失） | 0% (0/1) | 0% (0/1) |

两臂的已加载正文同样丢失（0%）——差别在**可恢复性**：插件臂的访问指引/清单/触发条件全部存活，
模型可自主重新检索（重读成本 ~1 次 okf_read）；skill 臂连"知识库存在、怎么查"都随摘要消失。
实测边界（OKF_COMPACTION_E2E=1）：对项目内的本地知识库，能力强的 Agent 仍可用 glob/grep/read
自主找回（3/3 答对）——但那是整文件探索路径（即压测中 S0 的 4-7x 成本鸿沟），且当知识库不在
项目目录内时此路不通；插件臂的清单注入保证知识库的存在性与访问方式永不依赖再探索。
